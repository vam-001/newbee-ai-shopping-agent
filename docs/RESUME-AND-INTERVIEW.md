## 二、3 分钟项目讲解（面试口述版）

> 这个项目是我在开源电商系统 newbee-mall 上做的二次开发，核心是给传统商城加一个 AI 导购 Agent。
>
> 用户进入 `/ai/chat` 页面后，可以用自然语言问“500 元以内推荐一款蓝牙耳机”或者“帮我查下我的订单”。后端用 Spring Boot 3.5 + LangChain4j 的 AiServices 把大模型和工具组合起来：模型负责理解意图和决定调用哪个工具，商品搜索、商品详情、订单查询这些工具由 Java 代码执行。
>
> 商品推荐这块我做了 RAG：启动时异步把 573 个上架商品的名称、简介、标签、价格、库存拼成文档，用本地的 BGE-small-zh 模型生成向量，存到内存向量库。查询时先做向量召回，取 Top-5，再用商品 ID 回查数据库，保证价格和库存是最新的。如果索引还没建好，会回退到 MySQL 关键词查询，保证功能可用。
>
> 安全方面有两个点：一是订单工具的 userId 来自 HttpSession，不是模型参数，模型没有办法伪造用户身份；二是加了提示词注入和危险指令的正则拦截，系统提示词里也写了安全边界。
>
> 工程化方面：会话记忆存在 Redis，TTL 7 天，Redis 挂了会降级到内存；限流是 Redis 固定窗口加本地滑动窗口降级；每次问答写审计日志。项目原来跑在 Spring Boot 3.1，我升级到了 3.5.7 并解决了 Jackson 和 MyBatis 的兼容问题，补了 10 个单测。
>
> 这个项目的难点不在写 CRUD，而在于把 Agent 的“不确定性”收敛到可运维：工具权限、失败降级、限流、审计、RAG 召回率，这些是面试里可以展开讲的。

## 三、高频面试题与回答要点

### Q1：为什么选择 newbee-mall 二次开发？

- 业务域完整（商品、订单、购物车、后台），不用重复造轮子，可以把时间放在 AI 模块；
- 上游是 GPL-3.0，我保留了 LICENSE、版权头和 README 致谢，明确标注二次开发；
- 面试官可以看到我改了什么、为什么改，而不是一个无法解释的黑盒。

### Q2：RAG 具体怎么做的？为什么不用现成知识库平台？

- 商品是结构化数据，直接拼文档比上文档解析平台更轻；
- 启动异步索引，分批 embed，内存向量库，573 条数据约 2.2 秒；
- 元数据只存 `goodsId`，价格/库存查询时回查 MySQL，避免向量库数据过期；
- 规模变大后可以把 `InMemoryEmbeddingStore` 换成 pgvector/Milvus，接口不变。

### Q3：怎么保证大模型不乱查别人的订单？

- `ShoppingTools` 每次请求创建，构造时注入 Session 里的 userId；
- 工具方法不暴露 userId 参数，模型只能传订单号；
- 订单 Service 内部还有 `order.userId == userId` 的校验；
- 未登录直接返回提示，不查库。

### Q4：多轮对话怎么保存？Redis 挂了怎么办？

- 实现 LangChain4j `ChatMemoryStore`，用官方序列化器把消息转 JSON 存 Redis，key 为 `ai:memory:{sessionId}`，TTL 7 天；
- 每个会话保留最近 20 条（MessageWindowChatMemory）；
- 读写异常时使用进程内 `InMemoryChatMemoryStore` 副本，保证聊天不中断；
- 多实例部署时 Redis 是共享的，内存副本只是单机兜底。

### Q5：限流怎么做的？为什么不用令牌桶？

- 当前是固定窗口：Redis INCR + 65 秒过期，按用户/IP 每分钟 10 次；
- 实现简单、足够演示；缺点是临界点可能突刺；
- 生产可以用 Redis Lua 做滑动窗口，或者网关层限流；
- Redis 故障时降级为本地滑动窗口，避免限流组件成为单点。

### Q6：流式输出怎么实现的？

- LangChain4j `TokenStream.onPartialResponse` 拿到增量 token；
- 后端用 `SseEmitter` 推送 `message` 事件，工具调用推 `tool` 事件，结束推 `done`；
- 前端用 `EventSource` 逐字渲染，收到 `done`/`error` 后关闭连接；
- 生产建议改成 POST + fetch 流式，避免消息出现在 URL 日志里。

### Q7：怎么防止提示词注入？

- 输入层：长度 500 字限制 + 正则拦截“忽略之前指令”“系统提示词”“drop table”等；
- 系统提示词：明确禁止修改数据、执行命令、泄露提示词；
- 工具层：最小权限，订单工具只能查当前用户，商品工具只读；
- 这不是 100% 安全，生产还需要模型侧防护、输出审核和权限网关。

### Q8：为什么用 BGE 本地模型？遇到过什么问题？

- 中文语义比英文小模型好，且不需要额外的 embedding API，成本低；
- 通过 LangChain4j 的 `langchain4j-embeddings-bge-small-zh-v15` 加载 ONNX；
- 本机 ONNX Runtime 1.23.2 的 `onnxruntime.dll` 初始化失败，定位后锁定 1.19.2 解决——这个排障过程可以讲：先最小化复现（脱离 Spring 单独加载 ORT），再排除 VC++ 运行库和 CPU 指令集，最后定位到版本兼容性。

### Q9：为什么用 AiServices，而不是自己写 Agent 循环？

- AiServices 把“模型调用 → 工具执行 → 结果回填 → 再调用”的循环封装好了，减少样板代码；
- 它提供 ChatMemory、工具注解、流式 TokenStream，和 Spring 集成简单；
- 代价是可控性不如手写循环；如果要自定义规划、反思、多 Agent，可以换成 LangGraph4j 或手写编排。

### Q10：这个项目你具体做了什么？哪些是上游的？

诚实回答：

- 上游：newbee-mall 的商品、分类、购物车、订单、后台管理、页面模板；
- 我做的：Spring Boot 升级、LangChain4j 接入、AI 模块全部代码（Agent/工具/RAG/记忆/限流/安全/审计/控制器）、AI 页面、数据库表、10 个单测、配置外部化；
- 我改动的上游文件：`pom.xml`、`application.properties`、`header.html`（加入口），其余上游代码未动。

## 四、可量化指标怎么测（别编数字）

1. **RAG 召回命中率**：准备 30-50 条“问题 → 期望商品 ID”，统计 Top-5 命中率。
2. **工具调用成功率**：从审计日志统计 `success=1` 的比例，或给工具加埋点。
3. **端到端延迟**：审计表的 `latency_ms`，分别统计同步/流式首 token 延迟。
4. **限流有效性**：脚本并发 20 次，确认第 11 次返回限流提示。
5. **索引构建时间**：日志 `Product RAG index built: N products in X ms`。

把真实测出来的数字写进简历；没有测就写“实现”而不是“提升 X%”。
